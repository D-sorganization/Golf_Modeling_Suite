# Assessment N Results: Visualization & Export

## Executive Summary

- The repository leverages robust visualization capabilities primarily built upon `matplotlib` and `pyvista` for 2D/3D physics representations.
- A centralized `launcher_theme.py` exists to apply consistent styling to `matplotlib` plots globally, demonstrating excellent foresight in uniform visual design.
- However, performance and memory management in rendering loops are problematic. `matplotlib.axes.Axes` scatter updates frequently cause UI thread freezing and memory leaks due to repeated element recreation instead of efficient `.set_offsets()` utilization.
- Data export capabilities are fragmented; scientific sweeps (e.g., `src/shared/python/optimization/`) serialize raw `.csv` and `.mat` files without offering standardized image export (SVG/PNG) or structured HDF5/Parquet options.
- The use of `matplotlib` inside PyQt/Tkinter GUIs is often synchronous, severely restricting scalability when dealing with high-frequency telemetry from the `realtime/controller.py`.

## Top 10 Visualization & Export Risks

1. **Critical:** Synchronous `matplotlib` rendering inside PyQt threads blocking the entire application GUI during complex scatter updates (e.g., `pendulum_renderer.py`).
2. **Major:** Memory leaks in continuous `matplotlib` animations resulting from the continuous addition of new artist objects instead of updating existing ones.
3. **Major:** Complex PyVista 3D scenes are completely rebuilt per frame rather than updating mesh coordinates.
4. **Major:** Missing export capabilities for vector graphics (SVG/PDF) in analytical tools, defaulting entirely to raw `.csv` outputs.
5. **Minor:** The `launcher_theme.py` is present but inconsistently applied across all engine modules, leading to mismatched visual aesthetics.
6. **Minor:** Mypy suppressions (`# type: ignore`) used heavily around `matplotlib` methods (e.g., `text`, `scatter`, `plot_surface`), creating type-safety blind spots.
7. **Minor:** Lack of interactive zoom/pan capabilities in static analysis reports generated by the testing suites.
8. **Minor:** Accessibility features (e.g., colorblind-safe palettes) are not formalized in the global styling configurations.
9. **Minor:** `matplotlib` is a heavy dependency causing slow imports (`ImportError` handling present in `launcher_theme.py`); deferred imports are not universally used.
10. **Minor:** Lack of standardized CSV export metadata headers (Git hash, seed, etc.) linking plots to their source artifacts.

## Refactoring Plan

**48 Hours**
- Fix the `pendulum_renderer.py` animation loop to use `.set_offsets()` on a single `scatter` artist instead of calling `ax.scatter()` repeatedly.
- Audit all GUI modules utilizing `matplotlib` to ensure rendering occurs asynchronously or via non-blocking `QThread` mechanisms.

**2 Weeks**
- Introduce standardized SVG/PNG export buttons/APIs to the plotting interfaces, reducing the need to rely on external software for `.csv` parsing.
- Refactor the global `launcher_theme.py` to enforce colorblind-safe palettes (e.g., utilizing `seaborn.color_palette("colorblind")`).

**6 Weeks**
- Transition heavy 3D rendering tasks (like the `PyVista` mesh visualization) to utilize efficient memory streaming rather than full object reconstruction per frame.
- Enable high-performance plotting alternatives (e.g., `pyqtgraph`) for high-Hz real-time telemetry from EtherCAT/UDP streams.
